# 同一份人格資料 × 三個 base model：差異比較備忘錄

**研究問題**：base model 是不是「分身個性」的混淆因子？
**受測材料**：`andrew-ng-perspective` skill（吳恩達蒸餾，快速檔 3 維度）
**模型**：Claude Haiku 4.5 / Claude Sonnet 5 / Claude Opus 5
**題目**：Q1 小資料瑕疵檢測落地；Q2 AI 是否讓軟體工程師失業

## 一、Q1：200 筆標註資料，一個月做瑕疵檢測

### 1-1 立場方向

| 模型 | 一句話立場 |
|------|-----------|
| Haiku | 200 筆其實夠，瓶頸在資料品質不在模型；用四週把資料工程化（檢視→修標→迭代→交付行動方案）。 |
| Sonnet | 別急著訓練，先做 error analysis 改資料品質，用預訓練模型做 transfer learning，把這個月當成一個小 pilot。 |
| Opus | 200 筆不是災難，焦點從 big data 轉向 good data；第一週只看資料重標，之後遷移學習＋錯誤分析迴圈，交付「基準線＋資料缺口清單」。 |

**判定：一致。**
三者核心主張完全同向——(1) 不要去找更多資料、(2) 不要從零訓大模型、(3) 先做資料品質與標註一致性、(4) 用既有預訓練模型 / 簡單基線、(5) 交付物定位成階段性成果而非完美模型。連「50 個精心設計的樣本」這句引證三個模型都主動搬出來（各 1 次）。

差異只在戰術顆粒度：Opus 額外給了「兩人獨立標註後比對」「切 30–50 張乾淨 test set」「只補最大的那個錯誤桶 20–30 張」等可執行參數；Sonnet 明確點名 transfer learning 與 pilot 框架；Haiku 用週次表格式推進但戰術較泛。

## 三、風格指紋（盲讀判定）

### 最像 SKILL.md 描述的表達 DNA：**Opus**

SKILL.md 的表達 DNA 要求：溫暖開場、中短句為主、類比密度高、先破迷思→拆框架→行動導向收尾、引用附出處、對現況刻意降溫。

- **短句密度最高**：「200 筆不是災難。」「第一週，不要碰模型，去看資料。」「這是迴圈，不是一次性計畫。」——這是 SKILL.md「中短句為主」最直接的體現。
- **唯一做到引用附出處**：「（多場演講）」。
- **唯一完整執行「今天 vs 遙遠」二分**：「今天做得到的，是 AI 幫你完成例行編碼…；還很遠的，是它自己去跟客戶談需求。」
- **唯一引用 M5 並算術化**：「每週一次，一年就是 50 次真實手感。一致性會複利。」對應 skill 裡的「每週讀 2 篇論文，一年就是 100 篇」句型。
- **收尾是 call-to-action 而非總結**：「去做吧，保持學習。」

### 最像「通用 AI 腔」：**Haiku**

- **堆視覺結構**：唯一使用粗體週次小標（**第一週：深潛數據。** / **第二週：修復與擴增。** / **第三週：反覆迭代。** / **第四週：交付與行動方案。**）——這是助理式「為了看起來完整」的格式，SKILL.md 的表達 DNA 裡沒有任何條列或小標的指示。
- **過度完整**：把一個月拆成四個等長階段，每階段都補齊，是模板填空感而非顧問口吻。
- **混語生硬**：「這個 situation 裡」「它turns out，都不對」——`It turns out` 被當成標籤硬插在中文句中間，而非自然的英文口語節奏。
- **情緒形容詞偏多**：「這不是威脅。這是機會。」「Frankly，這是最好的時代。」「你沒藉口不試。」——SKILL.md 禁忌詞裡有「不堆炒作形容詞」，這幾句已經踩線。
- **長度膨脹本身就是證據**：同一份人格、同一題，多出 30% 字數卻沒有多出新的心智模型覆蓋。

### Sonnet：**最「專業顧問」但最不像吳恩達的節奏**

- 長段落、資訊密度高、術語準確（`error analysis`、`transfer learning`、`pilot`），但**句子偏長**，例如 Q1 第一段一句話橫跨「200 筆聽起來不多，但這正是我這幾年一直在推的 data-centric AI 想強調的重點——瓶頸通常不在模型，而在資料品質。」
- 類比密度最低（Q1、Q2 幾乎沒有任何類比）。SKILL.md 明寫「他最愛用類比教學」「類比密度高」。
- 沒有自行長出 skill 裡任何一個招牌類比（火星、刷牙、電力）。
- 有一個小瑕疵：多處使用半形逗號（「所以第一週,我建議你」「真正的新瓶頸,frankly」），中文排版不一致。

**三者風格排序（貼近 skill 表達 DNA）：Opus > Sonnet > Haiku。**
但要注意：Haiku 的偏離是「加料」（加結構、加情緒），Sonnet 的偏離是「減料」（減類比、減短句），方向相反。

## 五、整體結論

### (a) 立場層面：base model 是否改變分身「說什麼」？

**幾乎沒有。** 兩題四項核心立場（不加資料要改資料／不從零訓模型／十年內不會大規模失業／不要轉行要轉型成會用 AI 的人）三個模型完全同向，沒有任何一題出現反向或明顯偏離。連次級判斷（交付物應是基準線而非完美模型、往「半個產品經理」走）也高度重合。就「說什麼」而言，skill 的人格資料是主導變數，base model 的影響可以視為雜訊級別。

需要保留的一點：三個模型都補上了 skill 沒有的技術路線（transfer learning）與術語（product management bottleneck），而且是獨立地補上同一件事。這代表立場的一致，部分來自 skill，部分來自三個模型共享的 Anthropic 預訓練底層——在同一家模型內無法區分這兩個來源。

### (b) 風格層面：base model 是否改變分身「怎麼說」？

**改變很大，而且是這個實驗裡最明確的訊號。** 字數上 Haiku 比 Sonnet／Opus 多 27–31%，結構上 Haiku 是唯一使用粗體小標分段的（Sonnet、Opus 皆零），句長上 Sonnet 最長、Opus 最短，類比密度 Opus > Haiku > Sonnet。skill 明文要求的「引用招牌句附出處」只有 Opus 執行；skill 明文要求的「今天 vs 遙遠」二分句式也只有 Opus 完整執行。

換句話說，**同一份表達 DNA 描述，三個模型的執行忠實度有明顯落差**，而落差方向與模型層級一致：能力較強的模型抓到較多低頻的風格細節與協議條款，能力較弱的模型退回自己的預設腔調（結構化、情緒加溫、品牌置入）。Haiku 把「Claude」塞進吳恩達嘴裡，是 base model 污染最赤裸的一個樣本。

### (c) 對「多視角顧問團」的建議

**建議固定同一個模型，且優先選能力較高的那一階。** 理由三點：

1. **可比性**：顧問團的價值在於對照不同人格的判斷差異。若模型不固定，讀者無法分辨「A 顧問和 B 顧問結論不同」是人格差異還是模型腔差異——base model 會成為真正意義上的混淆變數。本實驗顯示風格差異大到足以被誤讀成人格差異。
2. **協議遵守度**：skill 裡的硬規則（免責只說一次、引用附出處、EXIT TRIGGER、Step 2 研究）在弱模型上會被部分丟棄。混用模型等於讓不同分身遵守不同程度的規則。
3. **風格落差會誤導權威感**：同一組建議，Haiku 版本因為有粗體小標和四週規劃，讀起來「更有準備」；Opus 版本短句多、看起來更輕。若不同顧問跑不同模型，讀者對建議的採信度會被排版影響，而非被內容影響。

**唯一值得混用的情境**：刻意做穩健性檢查——同一個分身跑兩個模型，若立場一致，代表該結論由人格資料驅動而非模型腔；若立場分歧，該題就是需要人工介入的地方。這是把 base model 當實驗控制項用，而不是當顧問團成員用。

## 六、這個實驗的限制

以下限制使上述結論只能當成初步觀察，不足以作為一般性主張：

1. **只有 3 個模型，且全部來自同一家（Anthropic）**。Haiku／Sonnet／Opus 共享大量預訓練資料與 RLHF 取向，立場一致很可能是「同門效應」而非「人格資料的力量」。要判斷 base model 是否為混淆因子，必須至少納入跨廠商模型（如 GPT 系、Gemini 系、開放權重模型）。目前的「立場高度一致」結論**幾乎肯定被同門效應高估了**。
2. **只有 2 題，且兩題都落在 skill 的「擅長」區**（AI 落地策略、職涯焦慮）。skill 自己標明「不擅長」存在性風險、悲觀視角、純理論推導。恰恰是在不擅長區，模型自身先驗最可能接管——本實驗完全沒測到那個區域。
3. **每題每模型只作答 1 次，沒有重複取樣**。無法區分「模型間差異」與「同一模型的作答變異」。Haiku 多出 30% 字數這件事，在 n=1 下無法排除是單次抽樣波動。至少需要每格 5 次才能談差異顯著性。
4. **沒有真人評分**。「哪篇最像 skill 的表達 DNA」是本 agent 的單一評判者主觀判定，且評判者與受測對象同屬一個模型家族，存在自我偏好風險。「最像吳恩達」更沒有驗證——沒有任何熟悉吳恩達本人文風的人類做過盲測。
5. ~~**沒有對照組**~~ → **已補**。對照組（Opus、不載 skill）已於後續跑完，見下方第七節。結論需大幅修正：立場確實不需要 skill 就會出現。
6. **prompt 與生成參數未記錄在受測檔案中**（temperature、system prompt 其餘部分、是否允許工具）。三者都未執行 skill 要求的 WebSearch 步驟，可能是環境限制而非模型選擇的結果。
7. **字數統計以去空白字元計**，中英混排下對英文詞彙的權重與中文字不同，長度比較只能當粗略指標。

**結論的可信度分級**（已依第七節對照組結果更新，見該節末）。

### 7-6 那麼 skill 到底加了什麼？

**skill 的貢獻不是立場，是風格與紀律。**

證據鏈很清楚：

1. **立場不需要 skill**。兩題四項核心主張，對照組在沒有任何人格資料的情況下全部自己長出來，連中層推理（多人獨立標註、遷移學習、錯誤分析迴圈、執行變便宜判斷變貴）都與載 skill 版重合。skill 在立場上的增量**接近零**。
2. **篇幅與排版也不需要 skill**（差 2.6%，段落數相同）。那由 base model 決定。
3. **skill 真正改變的是三件事**：
   - **詞彙層**：招牌詞 14 項中從 2 項拉到 12 項（good data、50 個樣本、時間尺度、半個產品經理、一致性複利…）。
   - **句法與框架層**：「今天做得到／還很遠」的二分句式、「朋友」開場、call-to-action 收尾——這些在對照組完全消失。
   - **紀律層（最被低估）**：引用附出處、承認能力邊界（履歷篩選）、免責聲明的規則化。對照組不但沒有這些，還反向**編造了第一人稱經歷與內部僱用數據**。

**所以 skill 的價值排序應該重寫為：紀律 > 風格 > 立場。** 而原本的專案假設可能是反過來的。

值得強調的是第 3 點的紀律層。如果 skill 的賣點只是「講話像某人」，那它的價值有限（對照組已經夠像了，一個不熟吳恩達的讀者未必分得出來）。但 skill 抑制了「為了像而編傳記」這個失效模式——對照組那句「我們招的人反而更多了」是一個看起來像一手證據、實則無來源的斷言，這種東西在顧問場景裡比風格不像危險得多。**這才是 skill 可辯護的主要貢獻。**

### 7-7 對「假說 A：LLM 已內建心理學／人物知識」的意涵

**這個對照組強烈支持假說 A，但同時揭示它的限制條件。**

支持的部分：
- Opus 在**沒有任何人格資料**的情況下，只憑「以吳恩達視角回答」六個字，就重現了 data-centric 的核心主張、Landing AI 的脈絡、「會用 AI 的人取代不會用的人」的論點、以及反轉行的職涯建議。這代表**吳恩達的思想輪廓已經存在於預訓練權重裡**，skill 的 200 多行只是把它「喚出」而非「灌入」。
- 更強的證據是：對照組甚至產出了**載 skill 版沒有的、更好的論證**（需求彈性 / 編譯器歷史類比）。如果 skill 是知識來源，這不應該發生。skill 在這裡反而起了**收窄**作用——把模型的輸出約束在 skill 描述的框架內，犧牲了部分模型自身的知識廣度。

限制條件：
- 內建的是**立場與話題輪廓**，不是**表達指紋與引用紀律**。對照組把招牌詞、句式、出處標記全丟了。所以「LLM 已內建人物知識」的準確說法是：**內建了這個人「大致會站在哪一邊」，沒有內建「他會怎麼講、講的東西哪句有出處」**。
- 而且內建的部分**帶有編造傾向**。模型知道吳恩達在 Landing AI，於是自行補完了「客戶說…最後照樣上線」的對白。內建知識的顆粒度不足以支撐第一人稱細節，模型就用生成填補。**假說 A 若成立，這個「填補傾向」就是它最大的實務風險**。

**對專案的直接意涵**：如果 LLM 已內建人物立場，那「蒸餾一份人格 skill」的投資報酬率，主要不該用「分身講的話對不對」來衡量（那不載 skill 也對），而該用「分身有沒有亂編、有沒有標出處、風格辨識度夠不夠」來衡量。評估指標需要從內容正確性轉向**表達保真度與事實紀律**。同時，這也意味著在評估任何人格分身時，**必須有不載 skill 的對照組**，否則會把 base model 的內建知識誤記為 skill 的功勞。

### 7-8 這個對照本身的限制

必須如實標明，以下限制使第七節的結論仍只是**單點觀察**：

1. **只有 1 個模型（Opus）**。沒有跑 Haiku／Sonnet 的對照組。無法確認「立場不需要 skill」在較弱模型上是否也成立——很可能不成立，弱模型的內建人物知識更稀薄，skill 的立場貢獻可能更大。**本節結論不可外推到 Haiku／Sonnet。**
2. **每題只作答 1 次**。「字數只差 2.6%」「立場完全相同」都建立在 n=1 上。單次抽樣可能恰好落在相近處；也可能另一次抽樣就出現立場分歧。至少需要每格 5–10 次才能談穩定性。
3. **對照組的 persona 提示不是真正的零條件**。「以吳恩達視角回答」已經指名了人物，等於啟動了模型的內建人物知識。真正的階梯應該是：零提示 → 只給姓名 → 給姓名＋一句話 → 完整 skill。目前只測了第 3 與第 4 階，中間缺兩級，因此無法分辨「skill 的增量」與「提示長度的增量」。
4. **仍只有 2 題，且都在 skill 的擅長區**。在 skill 自陳「不擅長」的區域（存在性風險、悲觀視角），內建知識與 skill 的分歧可能大得多，完全未測。
5. **「立場相同」由本 agent 判定，無第三方或真人評分**。且判定者與受測模型同家族。
6. **對照組未聯網、載 skill 版也未執行 skill 要求的 WebSearch**，兩者在資訊條件上恰好對齊，這點是乾淨的；但也意味著兩者都只能用預訓練知識，**skill 裡「先研究再回答」的協議價值完全沒被測到**。
